## Time Complexity


Time complexity is used when analyzing the execution time of an algorithm.
Since execution time is measured differently depending on the execution environment, execution time is evaluated by the number of executions of basic operations.


<br>
<br>
<br>


>
### Basic Operations


1. Data input/output - copy, move...


2. Arithmetic operations - add, multiply ...


3. Control operations - if, while ...



<br>
<br>
<br>
>
### Types


- O (Big-O): Worst-case time complexity
- Ω (Omega): Best-case time complexity
- Θ (Theta): Average-case time complexity


When answering the question, "What is the time complexity of this code?", which we commonly ask, we are referring to time complexity expressed using Big-O notation.


**Because Big-O notation considers the worst case, it allows us to think in advance about the longest possible time during the program's execution.
**


<br>
<br>
<br>
>
### Big-O time complexity evaluates an algorithm approximately using the following methods.


- Assume only the worst-case situation
	- Do not assume the best-case situation (Big-Omega), where, luckily, numbers that are easy to calculate mentally appear.
	- Do not calculate what the average situation (Big-Theta) is, because it is not easy to define the 'average situation' for multiplication.
- The fewer operations there are, the more efficient the algorithm is considered to be. Other variables (such as hardware performance) are ignored.
The number of operations is also not counted exactly, but roughly estimated.


It should not be forgotten that time complexity is calculated 'approximately' rather than 'exactly'. Numerous factors that affect the performance of actual software (hardware performance, proper use of the memory hierarchy, whether caching is used, etc.) are all ignored. This is not because they are unimportant, but because they are difficult to calculate.

### Let's Calculate Time Complexity


#### Criteria for Counting Operations
- Assignment
- Four arithmetic operations


Let's calculate!


>
**O(1)**


```C
// 1번 코드
int sum = (x+1)*x/2;
```


In the case of code 2, '(x+1)' is calculated once, '*x' once, and '/2' once, and the result is assigned to sum once, for a total of four operations. However, in Big-O notation, this becomes O(1).
>
**O(1)**


```C
// 2번 코드
int sum = 0;
for(int i = 0; i<n; i++){
	sum+=i;
}
```


In code 1, 'sum=0' is performed once, 'int i = 0' once, 'i++' n times, and 'sum+=i' n times, for a total of 2n+2 operations.
In Big-O notation, only the highest-order term is written without its coefficient, so this becomes O(1).
>
**O(n²)**


```C
// 3번 코드
int sum = 0;
for(int i = 0; i<n; i++){
	for(int j = 0; j<i;j++){
    	sum+=j;
    }
}
```


The outer loop in code 3 repeats n times, while the inner loop repeats according to the value of i.
i changes from 0 to n-1, and since the inner loop repeats the corresponding number of times for each i, it repeats 0+1+2+...+(n-1) = n*(n-1)/2 times (the sum formula for an arithmetic sequence).
If only the highest-order term is written without its coefficient, this also becomes O(n²).
>
**O(N)<logN repetitions>**
```C
// 4번 코드
int sum = 0;
for(int i = n; i>0; i/=2){
	for(int j = 0; j<i; j++){
    	sum+=j;
    }
}
```


In code 4, the outer loop repeats logN times, while the number of repetitions of the inner loop varies according to the value of i.
(💡 The reason it repeats logN times is that i/=2.)
i changes from n to 1, and since the inner loop repeats the corresponding number of times for each i, it repeats n+(n/2)+(n/4)+..+1 = 2n times, making it O(N).

## Why Consider Time Complexity


Time complexity was created to determine which method (algorithm) is more efficient among various solutions.


ex) There are two algorithms for looking up one person among the 50 million people in Korea. 

 


Algorithm A: O(log n)


Algorithm B: O(n^2)

 


->Algorithm A performs 25 operations, while Algorithm B performs 2500000000000000 operations. 


->Algorithm A takes less than 1 second. 


->Algorithm B takes about 120 days..


Even so, we always make an effort to reduce time complexity so that we do not waste the valuable resource of time.


This effort is called optimization.

## Summary
In short, Big-O notation can be summarized as follows:
1) Count the number of operations.
2) Keep only the highest degree. ex) O(n²+n) => O(n²)
3) Boldly discard coefficients and constants. ex) O(2n+3) => O(n)
cf) The time complexity of built-in functions can be found in the official documentation.
